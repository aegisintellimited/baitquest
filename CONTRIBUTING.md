# Contributing to BaitQuest

Thanks for your interest in BaitQuest.

## Current project stage

BaitQuest is in product discovery and UX validation. Please do not begin production implementation based only on this scaffold. Product decisions, the clickable prototype, architecture and BDD acceptance criteria must be reviewed first.

## Working principles

- Keep confirmed decisions, proposals and open questions clearly distinguished.
- Prefer small, reviewable changes with tests.
- Protect privacy and avoid collecting unnecessary personal data.
- Do not add external analytics, infrastructure dependencies or services without an explicit design decision.
- Preserve the separation between mission content, presentation/theme, game rules/scoring and persistence.
- Never commit secrets, real personal data or customer data in code, issues, test fixtures or screenshots.
- Do not claim a feature is production-ready unless its acceptance criteria and required tests pass.

## Before opening a pull request

1. Search existing issues and discussions to avoid duplicating work.
2. For substantial product or architecture changes, open an issue first.
3. Explain the problem, proposed change and relevant trade-offs.
4. Add or update tests when implementation exists and update documentation when behaviour or decisions change.
5. Call out security, privacy, accessibility, data-integrity and migration implications.

## Pull requests

Include:
- The problem being addressed and the proposed change.
- Tests or validation performed, or why tests are not yet applicable.
- Security, privacy, accessibility and data-migration implications.
- Any changes to product behaviour or acceptance criteria.

## Questions

Use GitHub issues for public project questions that do not disclose security-sensitive information. Report suspected vulnerabilities privately as described in [SECURITY.md](SECURITY.md).
